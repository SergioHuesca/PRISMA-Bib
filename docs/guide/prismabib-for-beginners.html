Part 1: Install the app on Windows

This part takes you from an empty Windows computer to an installed app that has passed a check. You will install two programs, run one line that installs the app, and then check the result. Type each command into a terminal and press Enter.

What you need

  • uv, the program that installs the app. uv also provides Python 3.11 or newer, so you do not install Python yourself. The one exception is the Smart App Control fallback in section 4.
  • git, the program that the app checks for the first time it runs.
  • A terminal, which Windows already has. Section 1 shows how to open it.
  • An internet connection. The install line downloads the app, and later the app searches OpenAlex over the internet.

1. Open a terminal

A terminal is a window where you type a command, press Enter, and read the answer as text. You type every command in this part into one.

To open one on Windows, press the Windows key, type PowerShell, and press Enter. A window opens with a line of text that ends in >. That line is the prompt, and it is where you type.

After you install a program, close this terminal and open a new one. Windows finds a newly installed program only in a window that was opened after the install.

2. Install uv

This command installs uv with winget, the Windows package tool. Type it and press Enter:

winget install --id=astral-sh.uv -e

You should see winget print lines about finding, downloading and installing uv. When it finishes, the prompt comes back. The exact lines vary, so do not match them word for word.

[lines from winget about uv, then the prompt]

Close the terminal, open a new one, and check that uv is found:

uv --version

You should see uv followed by a version number:

uv 0.x.y

If it fails:

  • winget is not recognized: install uv by following the Windows instructions on docs.astral.sh/uv, the page the app names for uv. Then open a new terminal.
  • uv is not recognized after the install: close the terminal, open a new one, and run uv --version again. If it still fails, run the winget command again and let it finish.
  • winget stopped before the end: run the same winget command again.

3. Install git and check that it is found

This command installs git with winget. Type it and press Enter. Windows may ask whether the installer may make changes to your computer; answer Yes, or the install stops.

winget install --id Git.Git -e --source winget

You should see winget print lines about the git download and install. When it finishes, the prompt comes back.

[lines from winget about git, then the prompt]

Close the terminal, open a new one, and check that git is found:

git --version

You should see git version followed by a version number:

git version 2.x.x.windows.1

If it fails:

  • git is not recognized: close the terminal, open a new one, and run git --version again. If it still fails, run the winget command above again and let it finish.
  • winget is not recognized: install git with the Windows installer on git-scm.com, the site the app names for git. Then open a new terminal.
  • The winget command stopped before the end: run it again.

4. If Smart App Control blocks the program

Windows can use Smart App Control or Application Control. These features can block a program that Windows does not trust, and then the install or the app does not start. The app's own check gives the same advice. If this happens, use a Python installed from python.org, not the Python that uv would download. Use this fallback only when Windows blocks the install. It is the only place in Part 1 where you install Python yourself.

  1. Install Python 3.11 or newer from python.org, using the Windows installer on that site. Do not use a Python from the Microsoft Store or a portable copy. In the installer, tick the option that adds Python to PATH.
  2. Open a new terminal and check that Windows finds this Python:
python --version

You should see Python followed by version 3.11 or a newer one:

Python 3.x.x
  1. In that same terminal window, tell uv to use only a Python that is already on this computer. This setting lasts until you close the window.
$env:UV_PYTHON_PREFERENCE = "only-system"
(no output: the prompt comes back)

Then, in the same window, run the install line in section 5.

If it fails:

  • python is not recognized: run the python.org installer again and tick the option that adds Python to PATH.
  • python --version prints a version below 3.11: install 3.11 or a newer version from python.org.
  • The install in section 5 still says it cannot find Python: open a new terminal, run the two lines of this section again, and then the install line in section 5.
  • Windows still blocks the program: ask the project's maintainer on the project's GitHub Issues page before you change any Windows security setting.

5. Install the app with one line

This line downloads the app from the project's public GitHub repository and installs it, so that its command, prismabib, runs from any folder. Type it and press Enter:

uv tool install "prismabib[gui] @ git+https://github.com/SergioHuesca/PRISMA-Bib"

The line has four parts:

  • uv tool install asks uv to install a command-line program in its own area, which uv manages. The program stays apart from other Python programs on your computer.
  • prismabib is the name of the app's package, and the command you will type later.
  • [gui] adds the libraries that the browser app uses: Panel and param.
  • @ git+https://github.com/SergioHuesca/PRISMA-Bib says where the app comes from: the project's public GitHub repository. The install needs an internet connection. The double quotes keep the whole line together.

You should see uv print lines about the packages it downloads and installs. The exact lines depend on the uv version. When it finishes, the prompt comes back.

[lines from uv about downloading and installing packages, then the prompt]

If it fails:

  • The error mentions git, or the check says git was not found: go back to step 3, open a new terminal, and run the install line again.
  • uv is not recognized: go back to step 2 and check uv.
  • The error mentions Python or a blocked program: go to section 4.
  • The download fails with a network error: check your internet connection, then run the install line again.

6. Check the install

The app has a check, prismabib doctor. It looks at your computer and prints one line for each item. Open a new terminal, so that the new program is found, and run it:

prismabib doctor

Every line starts with ok, warn or FAIL. A healthy result looks like this. Your paths and version numbers will differ.

environment:
ok   python 3.x.x (<the Python that uv uses>)
ok   prismabib x.y.z
ok   platform: <your Windows version>
  hint: if Windows (Smart App Control / Application Control) blocks a program, use a Python installed from python.org (signed), not a store or portable build.
ok   git: <path to git>
ok   projects root: <a folder>, writable (does not exist yet; it is created on first use)
ok   .env: not present (created by `prismabib credentials set`)

The check passes when no line starts with FAIL. A warn line is a note that does not stop the app. The hint line is a tip, not an error.

If it fails:

  • FAIL git: not found on PATH: go back to step 3, open a new terminal, and run the check again.
  • A FAIL line about the projects root says it is not writable: open a terminal in a folder you can write to, such as a folder in your own user account, and run the check again.
  • prismabib is not recognized: see the fix in "If prismabib is not recognized" at the end of this part.

Mac and Linux: taken from the project's documentation, not run by the authors

  1. Install uv and git. Follow the install instructions on docs.astral.sh/uv and git-scm.com, the sites the app names for these programs.

7. The firewall prompt

The first time you start the app, which you will do later in this guide, Windows may ask whether to allow the app through the firewall. This prompt comes from Windows, not from the app. Choose Private networks only or Cancel. Either choice lets the app run, because the app talks only to this computer.

8. The app listens only on your computer

When the app runs, it listens on the address 127.0.0.1, which means this computer. The app refuses any other address, so other computers cannot connect to it. Your searches still go out over the internet, because they go to OpenAlex.

If prismabib is not recognized

If the terminal says the prismabib command is not recognized, uv has not yet added its folder to your PATH list. This command adds it:

uv tool update-shell

You should see a message from uv about that folder. Its exact words vary. Then close the terminal, open a new one, and run prismabib doctor again.

[a message from uv about the folder]

If it fails:

  • It is still not recognized in a new terminal: run uv tool update-shell again, close the terminal, and open a new one.
  • uv is not recognized: go back to step 2.
  • The message from uv reports an error: copy the message and ask the project's maintainer on the project's GitHub Issues page.

If the git or uv install did not finish

If an install stopped early, do not repair files by hand. Run the same winget commands again, one for uv and one for git:

winget install --id=astral-sh.uv -e
winget install --id Git.Git -e --source winget
[lines from winget, then the prompt]

Then check the program: uv --version for uv, or git --version for git.

If it fails:

  • It stops again with a network message: check your internet connection, then run the commands again.
  • winget is not recognized: follow the Windows install instructions on docs.astral.sh/uv for uv, or on git-scm.com for git.

When the check in section 6 shows no FAIL line, Part 1 is done. Continue to Part 2.

Part 2: Write the search

In this part you write the search on the Query screen of the app. The search is the list of words that the app sends to the database. The example in this guide searches OpenAlex for baseball, pose estimation and pitcher, for the years 2015 to 2026. Saving the query does not search anything. It only writes the search and the years into your project folder.

1. Add the search terms

Click the box under Search terms, type one word or phrase, and press Enter. The word appears as a chip, a small box with a remove button. Each search term is an alternative: the app joins the terms with OR, so a Record matches if it has at least one of them.

The worked example uses no search terms, so leave this box empty.

2. Add the compound term

A compound term is a group of parts that must all appear. Click the box under Compound terms, type baseball + pose estimation + pitcher, and press Enter. Put a space on each side of the plus sign. Without the spaces, the whole text becomes one phrase.

The app saves a compound term as its parts in quotation marks, joined by AND. For the example, the app saves this line in the project file (project.toml):

search = '"baseball" AND "pose estimation" AND "pitcher"'

The text between the outer single quotation marks is the search: "baseball" AND "pose estimation" AND "pitcher".

3. Set the years

In First year, type 2015. In Last year, type 2026. Both boxes are needed. The same years are copied to the Criteria screen, as Include from year and Include up to year, so they also apply as a screening rule.

4. Leave Subject areas empty

Leave Subject areas empty for this example. An empty list means no restriction. An empty box does not mean that nothing matches.

5. Save the query

Press Save query. The screen then shows Query saved to project.toml and criteria.yaml.

You can still change the query until the first capture starts. After that, the Query screen shows a notice that begins Read-only. and gives the reason. When a Run has started, the notice reads: The query is read-only because a Run has started. A different search needs a new Project. A Run that you discarded also counts, so it still locks the query.

If it did not go right

  • Add at least one search term or compound term. Add the compound term from step 2, then press Save query again.
  • OpenAlex searches have no grouping in this version: use search terms only, or a single compound term on its own. Remove the search terms, so that only the compound term remains.
  • Enter both the first and the last year. Type 2015 and 2026, then save again.
  • The notice Read-only. stays once a Run has started. Nothing is wrong. To search differently, start a new Project.

The example count

The example returned 108 Records on 2026-11-05, the date the repository documents. The count may differ today, because OpenAlex's counts change over time. Part 3 shows where the count of Records appears in the app.

If you have Scopus

Read this only if your Source mode uses Scopus. The steps above still apply. There are three differences. This guide does not walk through a Scopus capture.

  1. Subject areas is disabled, and the screen shows why: Restricting by subject area with Scopus needs Enrichment, which this version does not offer.
  2. In the size check, Check the size of the Scopus search shows the quota cost and the remaining weekly allowance, as Quota cost and Remaining weekly allowance. It shows no reset time. The OpenAlex check shows when its daily allowance resets.
  3. A capture needs a key entitled to the full view, which the software calls COMPLETE. If your key does not have it, the app refuses the capture and does not fall back to a lower view. The screen then shows the general key message A key is missing, or the service did not accept it. and suggests checking the key. A valid key can show that message too, because the refusal is about the view. The size check does not need the full view, so it can succeed before a capture is refused.

Elsevier and your institution decide which views your key can use. You find out only by trying.

For the difference between a query and criteria, read the page named Build a Scopus Query in this documentation. You can open it here: Build a Scopus Query.

Parte 1: Instalar la aplicación en Windows

Esta parte le lleva desde un equipo Windows sin nada instalado hasta una aplicación instalada que ha superado una comprobación. Instalará dos programas, ejecutará una línea que instala la aplicación y después comprobará el resultado. Escriba cada comando en una terminal y pulse Enter.

Lo que necesita

  • uv, el programa que instala la aplicación. uv también proporciona Python 3.11 o una versión más reciente, así que usted no instala Python por su cuenta. La única excepción es la alternativa de Smart App Control de la sección 4.
  • git, el programa que la aplicación busca la primera vez que se ejecuta.
  • Una terminal, que Windows ya tiene. La sección 1 explica cómo abrirla.
  • Conexión a internet. La línea de instalación descarga la aplicación, y más adelante la aplicación busca en OpenAlex por internet.

1. Abrir una terminal

Una terminal es una ventana donde escribe un comando, pulsa Enter y lee la respuesta en forma de texto. Escribirá en una terminal todos los comandos de esta parte.

Para abrir una en Windows, pulse la tecla de Windows, escriba PowerShell y pulse Enter. Se abre una ventana con una línea de texto que termina en >. Esa línea es el indicador, y es donde se escribe.

Después de instalar un programa, cierre esta terminal y abra una nueva. Windows encuentra un programa recién instalado solo en una ventana que se abrió después de la instalación.

2. Instalar uv

Este comando instala uv con winget, la herramienta de paquetes de Windows. Escríbalo y pulse Enter:

winget install --id=astral-sh.uv -e

Debe ver que winget muestra líneas sobre la búsqueda, la descarga y la instalación de uv. Cuando termina, vuelve el indicador. Las líneas exactas varían, así que no las compare palabra por palabra.

[líneas de winget sobre uv, y después el indicador]

Cierre la terminal, abra una nueva y compruebe que se encuentra uv:

Debe ver uv seguido de un número de versión:

Debe ver que winget muestra líneas sobre la descarga y la instalación de git. Cuando termina, vuelve el indicador.

[líneas de winget sobre git, y después el indicador]

Debe ver git version seguido de un número de versión:

git version 2.x.x.windows.1

Si no funcionó:

  • git no se reconoce: cierre la terminal, abra una nueva y ejecute otra vez git --version. Si sigue fallando, ejecute otra vez el comando de winget de arriba y deje que termine.
  • winget no se reconoce: instale git con el instalador para Windows de git-scm.com, el sitio que la aplicación indica para git. Después abra una terminal nueva.
  • El comando de winget se detuvo antes del final: ejecútelo otra vez.

4. Si Smart App Control bloquea el programa

Windows puede usar Smart App Control o Application Control. Estas funciones pueden bloquear un programa en el que Windows no confía, y entonces la instalación o la aplicación no arrancan. El propio consejo de comprobación de la aplicación dice lo mismo. Si ocurre, use un Python instalado desde python.org, y no el Python que uv descargaría. Use esta alternativa solo cuando Windows bloquee la instalación. Es el único lugar de la Parte 1 donde usted instala Python por su cuenta.

  2. Abra una terminal nueva y compruebe que Windows encuentra este Python:
python --version

Debe ver Python seguido de la versión 3.11 o de una más reciente:

Python 3.x.x
  1. En esa misma ventana de terminal, indique a uv que use solo un Python que ya esté en este equipo. Este ajuste dura hasta que cierre la ventana.
$env:UV_PYTHON_PREFERENCE = "only-system"
(sin salida: vuelve el indicador)

Después, en la misma ventana, ejecute la línea de instalación de la sección 5.

Si no funcionó:

  • python no se reconoce: vuelva a ejecutar el instalador de python.org y marque la opción que añade Python al PATH.
  • python --version muestra una versión anterior a 3.11: instale desde python.org la versión 3.11 o una más reciente.
  • La instalación de la sección 5 sigue diciendo que no encuentra Python: abra una terminal nueva, ejecute otra vez las dos líneas de esta sección y después la línea de la sección 5.
  • Windows sigue bloqueando el programa: pregunte al responsable del proyecto en la página de Issues de GitHub del proyecto antes de cambiar cualquier ajuste de seguridad de Windows.

  • prismabib es el nombre del paquete de la aplicación, y el comando que escribirá más adelante.

Parte 2: Escribe la búsqueda

En esta parte escribes la búsqueda en la pantalla Query de la aplicación. La búsqueda es la lista de palabras que la aplicación envía a la base de datos. El ejemplo de esta guía busca en OpenAlex baseball, pose estimation y pitcher, para los años 2015 a 2026. Guardar la búsqueda no busca nada: solo escribe la búsqueda y los años en la carpeta de tu proyecto.

1. Añade los términos de búsqueda

Haz clic en el recuadro debajo de Search terms, escribe una palabra o una frase y pulsa Enter. La palabra aparece como una ficha, un recuadro pequeño con un botón para quitarla. Cada término de búsqueda es una alternativa: la aplicación los une con OR, así que un registro coincide si tiene al menos uno de ellos.

El ejemplo de la guía no usa términos de búsqueda, así que deja este recuadro vacío.

2. Añade el término compuesto

Un término compuesto es un grupo de partes que deben aparecer todas. Haz clic en el recuadro debajo de Compound terms, escribe baseball + pose estimation + pitcher y pulsa Enter. Deja un espacio a cada lado del signo más. Sin los espacios, todo el texto se convierte en una sola frase.

La aplicación guarda un término compuesto como sus partes entre comillas, unidas por AND. Para el ejemplo, la aplicación guarda esta línea en el archivo del proyecto (project.toml):

search = '"baseball" AND "pose estimation" AND "pitcher"'

El texto entre las comillas simples exteriores es la búsqueda: "baseball" AND "pose estimation" AND "pitcher".

3. Indica los años

En First year, escribe 2015. En Last year, escribe 2026. Hacen falta los dos. Los mismos años se copian a la pantalla Criteria, como Include from year e Include up to year, así que también se aplican como regla de cribado.

4. Deja Subject areas vacío

Deja Subject areas vacío en este ejemplo. Una lista vacía significa sin restricción. Un recuadro vacío no significa que no coincida nada.

5. Guarda la búsqueda

Pulsa Save query. La pantalla muestra entonces Query saved to project.toml and criteria.yaml.

Puedes seguir cambiando la búsqueda hasta que empiece la primera captura. Después, la pantalla Query muestra un aviso que empieza por Read-only. y da el motivo. Cuando ya ha empezado una ejecución, el aviso dice: The query is read-only because a Run has started. A different search needs a new Project. Una ejecución que descartaste también cuenta, así que sigue bloqueando la búsqueda.

Si algo no sale bien

  • Add at least one search term or compound term. Añade el término compuesto del paso 2 y pulsa Save query otra vez.
  • OpenAlex searches have no grouping in this version: use search terms only, or a single compound term on its own. Quita los términos de búsqueda, para que solo quede el término compuesto.
  • Enter both the first and the last year. Escribe 2015 y 2026, y guarda otra vez.
  • El aviso Read-only. permanece una vez que ha empezado una ejecución. No hay ningún error. Para buscar de otra manera, empieza un proyecto nuevo.

El recuento del ejemplo

El ejemplo devolvió 108 registros el 2026-11-05, la fecha que documenta el repositorio. Hoy el número puede ser distinto, porque los recuentos de OpenAlex cambian con el tiempo. La parte 3 muestra dónde aparece el recuento de registros en la aplicación.

Si tienes Scopus

Lee esto solo si tu modo de fuente usa Scopus. Los pasos anteriores siguen valiendo. Hay tres diferencias. Esta guía no recorre una captura de Scopus.

  1. Subject areas aparece desactivado, y la pantalla explica por qué: Restricting by subject area with Scopus needs Enrichment, which this version does not offer.
  2. En la comprobación de tamaño, Check the size of the Scopus search muestra el coste de cuota y la cuota semanal que queda, como Quota cost y Remaining weekly allowance. No muestra cuándo se reinicia. La comprobación de OpenAlex sí muestra cuándo se reinicia su cuota diaria.
  3. Una captura necesita una clave con derecho a la vista completa, que el software llama COMPLETE. Si tu clave no lo tiene, la aplicación rechaza la captura y no recurre a una vista inferior. La pantalla muestra entonces el mensaje general sobre la clave A key is missing, or the service did not accept it. y sugiere revisar la clave. Una clave válida también puede mostrar ese mensaje, porque el rechazo se refiere a la vista. La comprobación de tamaño no necesita la vista completa, así que puede funcionar antes de que una captura sea rechazada.

Elsevier y tu institución deciden qué vistas puede usar tu clave. Solo lo sabes al intentarlo.
