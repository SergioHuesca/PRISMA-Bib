Part 1: Install

First, install the app with one line. This command downloads the app and makes it available in your terminal.

uv tool install "prismabib[gui] @ git+https://github.com/SergioHuesca/PRISMA-Bib"

Then start the app with the command below. It opens the app in your browser. When you are done, press Stop the app.

prismabib gui

Part 3 (continued): Screen, count and export

This part covers the second half of Part 3: screening the Records, reading the Flow counts and exporting the results. The labels in bold are the words on the screen. They stay in English in both languages, so you can match them to what you see.

Read the Flow counts

The Flow counts screen shows the numbers of the PRISMA flow diagram, one line for each step. Read the table like this:

  • A minus sign in front of a number means that the number is taken away from the total above it.
  • An indented line is a breakdown of the line above it. It is not taken away a second time.
  • Every number is worked out from your stored data and your Decision log each time the table is drawn. No number is typed in by hand. The screen says so: These numbers are worked out again from the store and the Decision log each time.

The first line, Records identified (OpenAlex meta.count) for an OpenAlex review, is the number of Records that the searches reported, before anything is removed.

The table is redrawn when you press Refresh the Flow counts. Press it after each session of screening to see your Decisions move the right lines.

Screen the Records

Open the Screening step and press Start screening. Before you press it, check the name in the field Reviewer (recorded on every Decision you make here). The field starts with the reviewer name you entered when you created the Project. If the Project has no such name, it starts with the name saved in Settings. Every Decision you make here carries the name in this field.

Keep Blind mode: hide author names, citation counts and other reviewers' Decisions ticked. It is on by default. While it is on, the screen hides author names, citation counts and the Decisions of other reviewers, so that they do not sway your judgement. The header then reads Blind mode: on.

The keys below do the same as the buttons next to them. A key acts only when you are not typing in a text box. Inside a text box, the key is typed as text.

KeyWhat it doesButton on screen
iInclude the Record.include (i)
eExclude the Record. Press e, then the number of the reason (1 to 9). A number pressed on its own only reminds you to press e first.No single button. Use the numbered reason buttons, one for each of the first nine reason codes in your Criteria.
uMark the Record as unsure. It stays in the queue.unsure (u)
nGo to the next Record without deciding.next (n)
pGo back to the previous Record without deciding.prev (p)
zUndo your latest Decision on the Record on screen.undo (z)
?Show or hide the list of keys.help (?)

Each Decision is saved before the next Record appears, so if you stop, you lose at most the Record on screen. Every Decision stays in the Decision log. Practise with about ten Records before you decide the rest, and make each key press a Decision you mean to make.

Undo does not erase anything. It adds a new Unsure Decision to the Record on screen, and both the old Decision and the new one stay in the Decision log. The screen then reads undone: the Record now counts as Unsure (the log keeps both Decisions).

The header above each Record shows three counts. Unscreened: is the number of Records with no Decision yet. Unsure: is the number of Records whose latest Decision is Unsure. Records: is the total. An Unsure Record is not Unscreened: it has a Decision, and it stays in the queue.

When you have finished a session, go back to the Flow counts screen and press Refresh the Flow counts. An exclusion at this stage moves one Record into Excluded at title and abstract, and an inclusion moves one into Sought for full-text retrieval.

If the step fails:

  • The screen says Screening needs: and names what is missing. If the Criteria are missing, finish the Criteria step. If the store is missing, finish the Build step.
  • The screen says Loading the Records. Wait. The Screener appears when the loading ends.
  • If a sentence in bold appears, it names the problem and the next step. Take that step, then press Start screening again.

Register a Record the search missed (optional)

You can skip this part. Registering is needed only when you know of a Record that the search did not return. It is done on the Flow counts screen, under the heading Register a Record the search missed. A registered Record has its own line in the Flow counts. It is never added to the first line, and it is counted after the next build of the store.

The steps are described in Getting Started, Step 10. This guide does not walk through one prerequisite capture step that the section relies on: capturing the OpenAlex response for the Record you add. On the Flow counts screen, the section Get the OpenAlex responses for your candidates has the button Run the cascade for that capture. The link is relative, so it resolves on the built site. It does not resolve when this file is opened alone from disk, which is why the name of the page is written out here too.

Export the citable bundle

Open the Export step and press Export the citable bundle. A progress bar runs while the bundle is written. To stop it, press Cancel the export. A cancelled export changes nothing, and the bundle from the last export stays as it was. The screen says Stopped as you asked. Nothing was changed in the bundle.

The bundle goes into the exports folder inside your Project folder. When the export finishes, the screen names that folder and counts the files it wrote. The folder holds:

  • figures: the flow diagram, as an SVG file and a CSV file;
  • tables: each table as a CSV file, a Markdown file and a LaTeX file;
  • numbers.json: the numbers in the bundle;
  • records.csv and provenance_conflicts.csv;
  • manifest.json: what produced the numbers, including the criteria version, the run ids and the package version.

You can keep your own files, such as a manuscript, in the exports folder. Only the figures and tables folders are emptied and written again on each export. The other files are overwritten each time. Do not edit any of these files by hand. To change a number, correct the cause in the store or in the Decisions, then export again, so that the numbers stay reproducible.

After an export, the screen can show warnings. Each one starts with the word Warning. Read them before you cite a number.

  • If your Project folder is its own git repository and has uncommitted changes, the bundle does not describe a committed state of it. Commit your changes outside the app, then export again.
  • If your Project folder is its own git repository and its latest commit is on no remote branch, a reader cannot fetch that state. As far as the last fetch shows, the commit is not pushed. Push it outside the app, then export again.
  • If your Project folder is not its own git repository, or has no commit yet, the screen says that the bundle cannot name the state of your Project folder. This warning is expected when you installed the app with the one-line command and your Project folder is not a git repository of its own. The bundle records the state of the installed app instead, and the screen says what that state is. You do not need to fix anything. Cite the package version instead: the package_version line in manifest.json says which release produced the numbers.

Tasks that stay on the command line

Some tasks are not in the app and are not walked through here. They are filling a manuscript, full-text screening and enrichment. Amending the Criteria after screening starts is also a command-line task: the app locks the Criteria once a Decision has been logged. When you reach one of these tasks, leave the app and use the command line. Getting Started has the command-line walkthrough.

Parte 3 (continuación): revisar, contar y exportar

Esta parte cubre la segunda mitad de la Parte 3: revisar los Records, leer los Flow counts y exportar los resultados. Las etiquetas en negrita son las palabras de la pantalla. Se quedan en inglés en los dos idiomas, para que puedas encontrarlas en lo que ves.

Leer los Flow counts

La pantalla Flow counts muestra los números del diagrama de flujo de PRISMA, una línea por cada paso. Lee la tabla así:

  • Un signo menos delante de un número significa que ese número se resta del total de arriba.
  • Una línea con sangría es un desglose de la línea de arriba. No se vuelve a restar.
  • Cada número se calcula a partir de tus datos guardados y del Decision log cada vez que se dibuja la tabla. Ningún número se escribe a mano. La pantalla lo dice, en inglés: These numbers are worked out again from the store and the Decision log each time.

La primera línea, Records identified (OpenAlex meta.count) en una revisión de OpenAlex, es el número de Records que reportaron las búsquedas, antes de que se quite nada.

La tabla se vuelve a dibujar cuando pulsas Refresh the Flow counts. Pulsa el botón al terminar cada sesión de revisión para ver cómo se mueven las líneas con tus Decisions.

Revisar los Records

Abre el paso Screening y pulsa Start screening. Antes de pulsarlo, revisa el nombre en el campo Reviewer (recorded on every Decision you make here). El campo empieza con el nombre de revisor que escribiste al crear el Project. Si el Project no tiene ese nombre, empieza con el nombre guardado en Settings. Cada Decision que tomes aquí lleva el nombre de este campo.

Deja marcada la casilla Blind mode: hide author names, citation counts and other reviewers' Decisions. Viene activada por defecto. Mientras está activada, la pantalla oculta los nombres de los autores, los recuentos de citas y las Decisions de otros revisores, para que no influyan en tu juicio. La cabecera dice entonces Blind mode: on.

Las teclas de la tabla hacen lo mismo que los botones que están junto a ellas. Una tecla funciona solo cuando no estás escribiendo en un cuadro de texto. Dentro de un cuadro de texto, la tecla se escribe como texto.

TeclaQué haceBotón en pantalla
iIncluye el Record.include (i)
eExcluye el Record. Pulsa e y luego el número del motivo (del 1 al 9). Un número pulsado solo te recuerda que antes hay que pulsar e.No hay un botón único. Usa los botones numerados de motivo, uno por cada uno de los nueve primeros códigos de motivo de tus Criteria.
uMarca el Record como Unsure. Se queda en la cola.unsure (u)
nPasa al Record siguiente sin decidir.next (n)
pVuelve al Record anterior sin decidir.prev (p)
zDeshace tu última Decision sobre el Record en pantalla.undo (z)
?Muestra u oculta la lista de teclas.help (?)

Cada Decision se guarda antes de que aparezca el Record siguiente, así que si paras, pierdes como mucho el Record que tienes en pantalla. Cada Decision queda en el Decision log. Practica con unos diez Records antes de decidir el resto, y haz que cada tecla que pulses sea una Decision que de verdad quieres tomar.

Undo no borra nada. Añade una Decision nueva, Unsure, al Record en pantalla, y tanto la Decision anterior como la nueva se quedan en el Decision log. Entonces la pantalla dice undone: the Record now counts as Unsure (the log keeps both Decisions).

La cabecera encima de cada Record muestra tres cifras. Unscreened: es el número de Records que todavía no tienen ninguna Decision. Unsure: es el número de Records cuya última Decision es Unsure. Records: es el total. Un Record Unsure no es Unscreened: ya tiene una Decision y se queda en la cola.

Al terminar una sesión, vuelve a la pantalla Flow counts y pulsa Refresh the Flow counts. Una exclusión en esta fase mueve un Record a Excluded at title and abstract, y una inclusión mueve uno a Sought for full-text retrieval.

Si no funcionó:

  • La pantalla dice Screening needs: y nombra lo que falta. Si faltan los Criteria, termina el paso Criteria. Si falta el store, termina el paso Build.
  • La pantalla dice Loading the Records. Espera. El Screener aparece cuando termina la carga.
  • Si aparece una frase en negrita, nombra el problema y el paso siguiente. Haz ese paso y pulsa de nuevo Start screening.

Registrar un Record que la búsqueda no encontró (opcional)

Puedes saltarte esta parte. Registrar solo hace falta si conoces un Record que la búsqueda no devolvió. Se hace en la pantalla Flow counts, bajo el encabezado Register a Record the search missed. Un Record registrado tiene su propia línea en los Flow counts. Nunca se suma a la primera línea, y se cuenta después de la siguiente construcción del store.

Los pasos están descritos en Getting Started, Step 10. Esta guía no recorre un paso previo de captura que esa sección necesita: capturar la respuesta de OpenAlex del Record que añades. En la pantalla Flow counts, la sección Get the OpenAlex responses for your candidates tiene para esa captura el botón Run the cascade. El enlace es relativo, así que se resuelve en el sitio publicado. No se resuelve cuando este archivo se abre solo desde el disco, por eso el nombre de la página también está escrito aquí.

Exportar el paquete citable

Abre el paso Export y pulsa Export the citable bundle. Mientras se escribe el paquete, aparece una barra de progreso. Para pararlo, pulsa Cancel the export. Una exportación cancelada no cambia nada, y el paquete de la última exportación se queda como estaba. La pantalla dice Stopped as you asked. Nothing was changed in the bundle.

El paquete se escribe en la carpeta exports dentro de la carpeta de tu Project. Al terminar, la pantalla nombra esa carpeta y cuenta los archivos escritos. La carpeta contiene:

  • figures: el diagrama de flujo, en un archivo SVG y en un archivo CSV;
  • tables: cada tabla en un archivo CSV, otro Markdown y otro LaTeX;
  • numbers.json: los números del paquete;
  • records.csv y provenance_conflicts.csv;
  • manifest.json: lo que produjo los números, con la versión de los Criteria, los identificadores de cada búsqueda y la versión del paquete.

Puedes guardar tus propios archivos, como un manuscrito, en la carpeta exports. Solo las carpetas figures y tables se vacían y se vuelven a escribir en cada exportación. Los demás archivos se sobrescriben cada vez. No edites ninguno de estos archivos a mano. Para cambiar un número, corrige la causa en el store o en las Decisions y exporta de nuevo, para que los números sigan siendo reproducibles.

Después de una exportación, la pantalla puede mostrar advertencias. Cada una empieza por la palabra Warning. Léelas antes de citar un número.

  • Si la carpeta de tu Project es un repositorio git propio y tiene cambios sin confirmar, el paquete no describe un estado confirmado de ella. Confirma tus cambios fuera de la app y exporta de nuevo.
  • Si la carpeta de tu Project es un repositorio git propio y su último commit no está en ninguna rama remota, un lector no puede obtener ese estado. Según la última descarga, el commit no está subido. Súbelo fuera de la app y exporta de nuevo.
  • Si la carpeta de tu Project no es un repositorio git propio, o todavía no tiene ningún commit, la pantalla dice que el paquete no puede nombrar el estado de tu carpeta de Project. Esta advertencia es lo esperable si instalaste la app con el comando de una sola línea y tu carpeta de Project no es un repositorio git propio. El paquete registra el estado de la app instalada, y la pantalla dice cuál es. No tienes que arreglar nada. Cita en su lugar la versión del paquete: la línea package_version de manifest.json indica qué versión produjo los números.

Tareas que quedan en la línea de comandos

Algunas tareas no están en la app y no se recorren aquí. Son rellenar un manuscrito, la revisión de texto completo (full-text screening) y el enriquecimiento (enrichment). Modificar los Criteria después de empezar la revisión también es una tarea de la línea de comandos: la app bloquea los Criteria en cuanto se registra una Decision. Cuando llegues a una de estas tareas, sal de la app y usa la línea de comandos. Getting Started tiene el recorrido por la línea de comandos.
