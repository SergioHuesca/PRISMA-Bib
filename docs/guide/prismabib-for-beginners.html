Part 1: Install the app on Windows

This part takes you from an empty Windows computer to an installed app that has passed a check. You will install two programs, run one line that installs the app, and then check the result. Type each command into a terminal and press Enter.

What you need

  • uv, the program that installs the app. uv also provides Python 3.11 or newer, so you do not install Python yourself. The one exception is the Smart App Control fallback in section 4.
  • git, the program that the app checks for the first time it runs.
  • A terminal, which Windows already has. Section 1 shows how to open it.
  • An internet connection. The install line downloads the app, and later the app searches OpenAlex over the internet.

1. Open a terminal

A terminal is a window where you type a command, press Enter, and read the answer as text. You type every command in this part into one.

To open one on Windows, press the Windows key, type PowerShell, and press Enter. A window opens with a line of text that ends in >. That line is the prompt, and it is where you type.

After you install a program, close this terminal and open a new one. Windows finds a newly installed program only in a window that was opened after the install.

2. Install uv

This command installs uv with winget, the Windows package tool. Type it and press Enter:

winget install --id=astral-sh.uv -e

You should see winget print lines about finding, downloading and installing uv. When it finishes, the prompt comes back. The exact lines vary, so do not match them word for word.

[lines from winget about uv, then the prompt]

Close the terminal, open a new one, and check that uv is found:

uv --version

You should see uv followed by a version number:

uv 0.x.y

If it fails:

  • winget is not recognized: install uv by following the Windows instructions on docs.astral.sh/uv, the page the app names for uv. Then open a new terminal.
  • uv is not recognized after the install: close the terminal, open a new one, and run uv --version again. If it still fails, run the winget command again and let it finish.
  • winget stopped before the end: run the same winget command again.

3. Install git and check that it is found

This command installs git with winget. Type it and press Enter. Windows may ask whether the installer may make changes to your computer; answer Yes, or the install stops.

winget install --id Git.Git -e --source winget

You should see winget print lines about the git download and install. When it finishes, the prompt comes back.

[lines from winget about git, then the prompt]

Close the terminal, open a new one, and check that git is found:

git --version

You should see git version followed by a version number:

git version 2.x.x.windows.1

If it fails:

  • git is not recognized: close the terminal, open a new one, and run git --version again. If it still fails, run the winget command above again and let it finish.
  • winget is not recognized: install git with the Windows installer on git-scm.com, the site the app names for git. Then open a new terminal.
  • The winget command stopped before the end: run it again.

4. If Smart App Control blocks the program

Windows can use Smart App Control or Application Control. These features can block a program that Windows does not trust, and then the install or the app does not start. The app's own check gives the same advice. If this happens, use a Python installed from python.org, not the Python that uv would download. Use this fallback only when Windows blocks the install. It is the only place in Part 1 where you install Python yourself.

  1. Install Python 3.11 or newer from python.org, using the Windows installer on that site. Do not use a Python from the Microsoft Store or a portable copy. In the installer, tick the option that adds Python to PATH.
  2. Open a new terminal and check that Windows finds this Python:
python --version

You should see Python followed by version 3.11 or a newer one:

Python 3.x.x
  1. In that same terminal window, tell uv to use only a Python that is already on this computer. This setting lasts until you close the window.
$env:UV_PYTHON_PREFERENCE = "only-system"
(no output: the prompt comes back)

Then, in the same window, run the install line in section 5.

If it fails:

  • python is not recognized: run the python.org installer again and tick the option that adds Python to PATH.
  • python --version prints a version below 3.11: install 3.11 or a newer version from python.org.
  • The install in section 5 still says it cannot find Python: open a new terminal, run the two lines of this section again, and then the install line in section 5.
  • Windows still blocks the program: ask the project's maintainer on the project's GitHub Issues page before you change any Windows security setting.

5. Install the app with one line

This line downloads the app from the project's public GitHub repository and installs it, so that its command, prismabib, runs from any folder. Type it and press Enter:

uv tool install "prismabib[gui] @ git+https://github.com/SergioHuesca/PRISMA-Bib"

The line has four parts:

  • uv tool install asks uv to install a command-line program in its own area, which uv manages. The program stays apart from other Python programs on your computer.
  • prismabib is the name of the app's package, and the command you will type later.
  • [gui] adds the libraries that the browser app uses: Panel and param.
  • @ git+https://github.com/SergioHuesca/PRISMA-Bib says where the app comes from: the project's public GitHub repository. The install needs an internet connection. The double quotes keep the whole line together.

You should see uv print lines about the packages it downloads and installs. The exact lines depend on the uv version. When it finishes, the prompt comes back.

[lines from uv about downloading and installing packages, then the prompt]

If it fails:

  • The error mentions git, or the check says git was not found: go back to step 3, open a new terminal, and run the install line again.
  • uv is not recognized: go back to step 2 and check uv.
  • The error mentions Python or a blocked program: go to section 4.
  • The download fails with a network error: check your internet connection, then run the install line again.

6. Check the install

The app has a check, prismabib doctor. It looks at your computer and prints one line for each item. Open a new terminal, so that the new program is found, and run it:

prismabib doctor

Every line starts with ok, warn or FAIL. A healthy result looks like this. Your paths and version numbers will differ.

environment:
ok   python 3.x.x (<the Python that uv uses>)
ok   prismabib x.y.z
ok   platform: <your Windows version>
  hint: if Windows (Smart App Control / Application Control) blocks a program, use a Python installed from python.org (signed), not a store or portable build.
ok   git: <path to git>
ok   projects root: <a folder>, writable (does not exist yet; it is created on first use)
ok   .env: not present (created by `prismabib credentials set`)

The check passes when no line starts with FAIL. A warn line is a note that does not stop the app. The hint line is a tip, not an error.

If it fails:

  • FAIL git: not found on PATH: go back to step 3, open a new terminal, and run the check again.
  • A FAIL line about the projects root says it is not writable: open a terminal in a folder you can write to, such as a folder in your own user account, and run the check again.
  • prismabib is not recognized: see the fix in "If prismabib is not recognized" at the end of this part.

Mac and Linux

Mac and Linux: taken from the project's documentation, not run by the authors

The steps in this box come from the project's documentation and its continuous-integration setup. The authors did not run these steps on a Mac or on Linux. Compare each step with what you see.

  1. Install uv and git. Follow the install instructions on docs.astral.sh/uv and git-scm.com, the sites the app names for these programs.
  2. Run the one-line install from section 5, unchanged:
uv tool install "prismabib[gui] @ git+https://github.com/SergioHuesca/PRISMA-Bib"
  1. Open a new terminal and run the check from section 6:
prismabib doctor

You should see the same kind of output as in section 6. If the command is not recognized, see "If prismabib is not recognized" at the end of this part.

7. The firewall prompt

The first time you start the app, which you will do later in this guide, Windows may ask whether to allow the app through the firewall. This prompt comes from Windows, not from the app. Choose Private networks only or Cancel. Either choice lets the app run, because the app talks only to this computer.

8. The app listens only on your computer

When the app runs, it listens on the address 127.0.0.1, which means this computer. The app refuses any other address, so other computers cannot connect to it. Your searches still go out over the internet, because they go to OpenAlex.

If prismabib is not recognized

If the terminal says the prismabib command is not recognized, uv has not yet added its folder to your PATH list. This command adds it:

uv tool update-shell

You should see a message from uv about that folder. Its exact words vary. Then close the terminal, open a new one, and run prismabib doctor again.

[a message from uv about the folder]

If it fails:

  • It is still not recognized in a new terminal: run uv tool update-shell again, close the terminal, and open a new one.
  • uv is not recognized: go back to step 2.
  • The message from uv reports an error: copy the message and ask the project's maintainer on the project's GitHub Issues page.

If the git or uv install did not finish

If an install stopped early, do not repair files by hand. Run the same winget commands again, one for uv and one for git:

winget install --id=astral-sh.uv -e
winget install --id Git.Git -e --source winget
[lines from winget, then the prompt]

Then check the program: uv --version for uv, or git --version for git.

If it fails:

  • It stops again with a network message: check your internet connection, then run the commands again.
  • winget is not recognized: follow the Windows install instructions on docs.astral.sh/uv for uv, or on git-scm.com for git.

When the check in section 6 shows no FAIL line, Part 1 is done. Continue to Part 2.

Part 2: Write the search

In this part you write the search on the Query screen of the app. The search is the list of words that the app sends to the database. The example in this guide searches OpenAlex for baseball, pose estimation and pitcher, for the years 2015 to 2026. Saving the query does not search anything. It only writes the search and the years into your project folder.

1. Add the search terms

Click the box under Search terms, type one word or phrase, and press Enter. The word appears as a chip, a small box with a remove button. Each search term is an alternative: the app joins the terms with OR, so a Record matches if it has at least one of them.

The worked example uses no search terms, so leave this box empty.

2. Add the compound term

A compound term is a group of parts that must all appear. Click the box under Compound terms, type baseball + pose estimation + pitcher, and press Enter. Put a space on each side of the plus sign. Without the spaces, the whole text becomes one phrase.

The app saves a compound term as its parts in quotation marks, joined by AND. For the example, the app saves this line in the project file (project.toml):

search = '"baseball" AND "pose estimation" AND "pitcher"'

The text between the outer single quotation marks is the search: "baseball" AND "pose estimation" AND "pitcher".

3. Set the years

In First year, type 2015. In Last year, type 2026. Both boxes are needed. The same years are copied to the Criteria screen, as Include from year and Include up to year, so they also apply as a screening rule.

4. Leave Subject areas empty

Leave Subject areas empty for this example. An empty list means no restriction. An empty box does not mean that nothing matches.

5. Save the query

Press Save query. The screen then shows Query saved to project.toml and criteria.yaml.

You can still change the query until the first capture starts. After that, the Query screen shows a notice that begins Read-only. and gives the reason. When a Run has started, the notice reads: The query is read-only because a Run has started. A different search needs a new Project. A Run that you discarded also counts, so it still locks the query.

If it did not go right

  • Add at least one search term or compound term. Add the compound term from step 2, then press Save query again.
  • OpenAlex searches have no grouping in this version: use search terms only, or a single compound term on its own. Remove the search terms, so that only the compound term remains.
  • Enter both the first and the last year. Type 2015 and 2026, then save again.
  • The notice Read-only. stays once a Run has started. Nothing is wrong. To search differently, start a new Project.

The example count

The example returned 108 Records on 2026-11-05, the date the repository documents. The count may differ today, because OpenAlex's counts change over time. Part 3 shows where the count of Records appears in the app.

If you have Scopus

Read this only if your Source mode uses Scopus. The steps above still apply. There are three differences. This guide does not walk through a Scopus capture.

  1. Subject areas is disabled, and the screen shows why: Restricting by subject area with Scopus needs Enrichment, which this version does not offer.
  2. In the size check, Check the size of the Scopus search shows the quota cost and the remaining weekly allowance, as Quota cost and Remaining weekly allowance. It shows no reset time. The OpenAlex check shows when its daily allowance resets.
  3. A capture needs a key entitled to the full view, which the software calls COMPLETE. If your key does not have it, the app refuses the capture and does not fall back to a lower view. The screen then shows the general key message A key is missing, or the service did not accept it. and suggests checking the key. A valid key can show that message too, because the refusal is about the view. The size check does not need the full view, so it can succeed before a capture is refused.

Elsevier and your institution decide which views your key can use. You find out only by trying.

For the difference between a query and criteria, read the page named Build a Scopus Query in this documentation. You can open it here: Build a Scopus Query.

Part 3a: Start the app and set it up

In this part you start the app, choose the folder where your Projects are kept, create a Project, and save a free OpenAlex key. No search runs in this part.

Start the app

In the terminal, run the command below. The app starts on your computer and opens in your browser. Keep the terminal window open while you use the app. Closing that window also stops the app.

prismabib gui

The terminal then shows a line like this:

prismabib is running at http://127.0.0.1:5006/ (Ctrl+C to stop)

The address points to your own computer: 127.0.0.1 is the local address. The number 5006 is the usual port. If that port is busy, the app picks another one and prints its address instead.

If the browser does not open by itself, copy the address from the terminal and paste it into your browser's address bar.

If something goes wrong

  • The browser did not open: copy the address the terminal printed, and paste it into your browser.
  • The terminal says the command was not found: the install in Part 1 did not finish. Run the install line from Part 1 again, open a new terminal window, and run the command again.
  • The terminal says No free port: close any programs that may be using network ports, then run the command again.

Stop the app

To stop the app, click “Stop the app” on the Home screen. If nothing is running, the app stops at once, and the browser page says that it has stopped. You can then close the tab.

If a task is running, such as a capture, the app asks you to confirm first. The page then shows “Yes, stop the app” and “Keep the app running”. Choose “Yes, stop the app” to stop: the running capture stops, the pages already fetched are kept, and a later capture picks up from them. Choose “Keep the app running” to go back without stopping.

You can also press Ctrl+C in the terminal. When nothing is left running, the terminal shows:

prismabib has stopped. Nothing running was left behind.

Choose the Projects folder

The Home screen has a box labelled “Projects folder”. The app keeps each Project in its own folder inside this one, and the Home screen shows the folder in use. Until you choose a folder, the app uses a folder named projects inside the folder the terminal was in when you started the app.

  1. Type a path into “Projects folder”.
  2. If the folder already exists, click “Use this folder”. If it does not exist yet, click “Create this folder” and the app creates it.
  3. Read the line under the buttons. When the folder is accepted, the line begins “Using” and shows the folder. The app remembers this folder for next time.

Avoid a folder inside a synced location such as OneDrive, Dropbox, Google Drive, iCloud or Box Sync. In that case the app shows a warning but still accepts the folder. Sync can lock or change files while the app is writing to them, so a folder outside sync is safer.

The app refuses three kinds of folder and says why under the buttons: a folder it cannot write to, a path that is too long, and a folder inside the installed program. A refusal changes nothing, so you can choose another folder straight away.

If something goes wrong

  • The message says the folder does not exist: click “Create this folder”, or check the spelling of the path.
  • The message says prismabib cannot write to this folder: choose a folder where your account can save files.
  • The message says the path is too long: choose a shorter path.

Create a Project

A Project holds one systematic review: its query, its eligibility criteria, its Records and its Decisions. The app never overwrites a Project. If a folder with the same name already exists, the app asks you to choose another Project name.

  1. On the Home screen, click “New Project”.
  2. In “Project name”, type a name, for example My first review. The app turns the name into a folder name and shows that folder name under the box.
  3. In “Reviewer name”, type your name. Every Decision in this Project carries that name. The app remembers it for the next Project.
  4. Answer “Do you have Scopus access?” by choosing “Yes”, “No” or “Not sure”. The app has no default answer, so you must choose one.
  5. Click “Create Project”.

Scopus access means a Scopus key with the COMPLETE view, which usually comes through an institution such as a university. If you are not sure, choose “Not sure”.

Your answer sets the Source mode, which means which databases this review searches. “No” and “Not sure” both create a Project in Source mode openalex, which searches OpenAlex only. That route needs a free OpenAlex key, which you get further down in this part, and it asks for no Scopus key. This part does not walk through the Scopus route.

When the Project is created, the screen shows:

Project my-first-review created with Source mode openalex.

The Project then opens at its first step that is not done, “Query”. Part 2 of this guide explains that step.

If something goes wrong

  • The app says a Project or a folder with that name already exists: type a different “Project name”.
  • The app says to enter the reviewer name: type your name in “Reviewer name”.
  • The app says the path is too long: choose a shorter Project name or a shorter Projects folder.
  • The app says you must answer the Scopus question: choose “Yes”, “No” or “Not sure”.

Get a free OpenAlex key

A real OpenAlex search needs a key. The key is a code that identifies your account. Create a free account on the OpenAlex website, openalex.org, and copy the API key from it.

Save the key and test it

Keys are saved in your per-user settings file, which is outside every Project folder. You enter the key in the Keys part of the “Source mode and keys” step.

  1. On the Home screen, click the Open button beside your Project in the list under Projects.
  2. In the sidebar, click “Source mode and keys”. The Keys part shows the settings file in a line that begins “Keys are saved in your per-user settings file”, followed by its location.
  3. Paste your key into “OpenAlex API key”. The box shows dots instead of the characters, so the key is not printed on screen.
  4. Click “Save OpenAlex key”. The app says the key is saved and clears the box.
  5. Click “Test OpenAlex key” and read the line it shows.

When the key is accepted, the app shows The key works. The line that begins “OpenAlex key comes from” shows where the app reads the key from. You can change the key later on the same screen: paste a new key, save it, and test it again.

If something goes wrong

  • The result says no key is set: paste the key into “OpenAlex API key” and click “Save OpenAlex key” first.
  • The result says 401: the key was rejected: copy the key again from your OpenAlex account, paste it in, save it, and test again.
  • The result says 403: check that your account may use this service, then test again.
  • The result is a network error: check your connection, then test again.

Part 3: Use the app end to end (continued)

This part takes you from the saved query to a built store. You save the rules, check how large the search is, capture the results and build the store. Button and field names are in bold and are quoted exactly as the app shows them in English.

Save the Criteria

The Criteria screen holds the rules that a Record must meet to stay in the review, and the reason codes you pick when you exclude a Record. Enter the reason codes for abstract screening in Reason codes for excluding at abstract screening, one per line. Full-text screening has its own list, in Reason codes for excluding at full-text screening.

In the Screener you press e and then a number key to choose a reason. The first code in the list is key 1, the second is key 2, and so on up to key 9. A code after the ninth has no number key, but you can still pick it with the mouse.

Enter the version in Criteria version (MAJOR.MINOR.PATCH) as three numbers separated by dots, for example 1.0.0. Raise the version whenever you change a rule, so that the history of your rules stays clear. The comments in the criteria file also ask you to commit each change to git.

Press Save Criteria. The screen confirms the save with the version you entered:

Criteria version 1.0.0 saved to criteria.yaml.

If something goes wrong

  • A message next to a field says the value is not a semantic version. Enter three numbers separated by dots, such as 1.0.0, and press Save Criteria again.
  • The screen says Some entries need correcting. Read the message next to each field, correct it, and press Save Criteria again.
  • The screen says The Criteria are read-only because a Decision has been logged. Once screening has started, the Criteria cannot be changed in the app. This guide does not cover the command-line route.
  • The screen says criteria.yaml has changed since you opened this form. Nothing was written. Leave the Criteria step, reopen it, and enter your changes again.

Check the size of the search

Press Check the size of the OpenAlex search before any capture. The check sends one request to OpenAlex and captures nothing. It writes nothing to your Project, so you can run it again as often as you like. For the worked example, the screen shows lines like these:

Records: 108
Cost bound: $0.00
Page budget: 2 pages
Remaining daily allowance: a number from OpenAlex
Allowance resets: a date and time in your local time zone

The line that begins with Records gives the number of Records the search matches in OpenAlex at the moment you check. Your number may differ from the example. The count is read from OpenAlex each time you press the button, and the Getting Started page notes that OpenAlex's counts change over time. The example returned 108 Records on 2026-11-05. A different figure is not an error.

The check then applies three rules to the Records count:

  • 2,000 Records or fewer: the check passes and you can continue.
  • More than 2,000 and up to 10,000 Records: the app shows a warning. Tick I understand this is a large set and want to continue to go on.
  • More than 10,000 Records: the app blocks the search and names the next step, which is to narrow the query. To narrow it, go to the Query screen, change the terms or the years, press Save query, and check again.

For OpenAlex, the screen also shows your daily allowance: how much of it is left, in OpenAlex's own units, and when it resets. The reset time is shown in your local time zone. OpenAlex search has a daily limit of 1,000 pages, and a capture counts against it.

If your Project searches Scopus, the check shows the quota cost instead. That is the number of requests the capture would use, together with the remaining weekly allowance. The screen gives no reset time for Scopus.

When the check passes, press Continue to capture. The capture controls appear below it.

If something goes wrong

  • The screen says a key is needed to check the size. Press Go to the keys step, add the key, and then press Check the size of the OpenAlex search again.
  • Continue to capture stays grey. Either the check blocked the search, or a warning is waiting for your tick. Narrow the query if the search is blocked, or tick the box if it only warns.
  • A sentence in bold appears under the check and names the problem and the next step. Read it, follow the next step, and check again. The saved query is unchanged.

Capture the search

Capturing fetches the search results from OpenAlex and keeps every page as it arrived. Set Page budget (pages of 100 works) to the most pages this run may fetch. The field starts at 10. The example needs 2 pages, so enter 2. A capture that reaches its budget stops, and you can resume it later.

OpenAlex calls the items it returns "works". This guide and the app call the same items Records, so the page budget counts pages of 100 Records each.

Tick I confirm: capture this search now, then press Start the capture. The app clears the tick box after every start, including a resume, so you tick it again each time.

While it runs, the screen shows a progress bar and counts like these:

Running. You can close the browser; the capture keeps going.
Pages done: 1. Records seen: 100 of 108.

Closing the browser does not stop the capture while the app runs. Keep the terminal window open, because the app keeps running in it.

To pause, press Cancel the capture. The capture stops after the page it is fetching is saved, and the pages already fetched are kept. Press Resume the capture later to carry on from the same point.

When every page has been fetched, the run is marked as Sealed:

Sealed. The capture is finished and can no longer be changed.

A Sealed run is complete and the app never changes it.

If something goes wrong

  • The screen says Check the size of the saved query first; it has changed or not run. Press Check the size of the OpenAlex search again, then tick the box and start.
  • The screen says Confirm that you want to capture before it starts. Tick I confirm: capture this search now, then press Start the capture.
  • The screen says the network stopped and that the pages already fetched are kept. Check your internet connection, then press Resume the capture.
  • The screen says OpenAlex's daily allowance is spent, and shows when it resets, in your local time. Wait until that time, then press Resume the capture.

Capture again, or discard an unfinished run

Capture again (a new run) starts a new run of the same search, even though a Sealed run already exists. The Sealed run stays as it is. The new run sends new requests to OpenAlex, so it spends your daily allowance again. Use it only when you need a fresh capture.

To discard an unsealed run you do not want, press Discard the unsealed run. The app asks you to confirm with Yes, discard it. Press Keep it to change your mind. Discarding deletes nothing: the pages already fetched stay on disk, and the discarded run is never resumed or sealed.

If something goes wrong

  • The screen says This capture is already Sealed. A Sealed run cannot be captured in place. Press Capture again (a new run) to start a new run.
  • The screen says The capture is running. Cancel it before discarding. Press Cancel the capture, wait for it to stop, and then discard.
  • Discard the unsealed run is grey. Only an unsealed run can be discarded, and a Sealed run cannot be discarded.

Build the store

The store is the set of Records built from your captured searches. Press Build the store. After the first build, the button reads Rebuild the store. While the build runs, the screen says Building. and shows its progress.

When the build finishes, the screen shows its result. For the example, it looks like this:

Built. The store holds 108 Records. 0 duplicates across searches were removed.

Your numbers will be your own. A Record that more than one search returned is counted once, and the second number tells you how many duplicates were removed.

A rebuild never touches your captured searches or your Decisions. The app replaces the store only when the new one is complete. To stop a build that is running, press Cancel the build. The app then says Stopped as you asked. and keeps the previous store.

If something goes wrong

  • The screen says The build failed. Read the sentence after it, fix the problem it names, and press Rebuild the store, or Build the store if there is no store yet.
  • The store seems out of date after new captures. Press Rebuild the store. A rebuild keeps your captured searches and Decisions.

Delete the built store

Deleting the built store is safe, because you can build it again from your captured searches. Press Delete the built store. The app then lists what goes and what stays. Press Yes, delete the store to delete it, or Keep the store to keep it.

Only the built store is deleted. Your captured searches and every Sealed run stay, and so do your Decision log, the Project's settings file and its Criteria file. The app never deletes any of these. After a delete, the screen says:

The store was deleted. Build the store to make it again.

If something goes wrong

  • The screen says A task is running. Wait for it to finish, or press Cancel the capture or Cancel the build, and then delete again.
  • The screen says The store could not be deleted, probably because another program has it open. Close that program and press Delete the built store again.

Parte 1: Instalar la aplicación en Windows

Esta parte le lleva desde un equipo Windows sin nada instalado hasta una aplicación instalada que ha superado una comprobación. Instalará dos programas, ejecutará una línea que instala la aplicación y después comprobará el resultado. Escriba cada comando en una terminal y pulse Enter.

Lo que necesita

  • uv, el programa que instala la aplicación. uv también proporciona Python 3.11 o una versión más reciente, así que usted no instala Python por su cuenta. La única excepción es la alternativa de Smart App Control de la sección 4.
  • git, el programa que la aplicación busca la primera vez que se ejecuta.
  • Una terminal, que Windows ya tiene. La sección 1 explica cómo abrirla.
  • Conexión a internet. La línea de instalación descarga la aplicación, y más adelante la aplicación busca en OpenAlex por internet.

1. Abrir una terminal

Una terminal es una ventana donde escribe un comando, pulsa Enter y lee la respuesta en forma de texto. Escribirá en una terminal todos los comandos de esta parte.

Para abrir una en Windows, pulse la tecla de Windows, escriba PowerShell y pulse Enter. Se abre una ventana con una línea de texto que termina en >. Esa línea es el indicador, y es donde se escribe.

Después de instalar un programa, cierre esta terminal y abra una nueva. Windows encuentra un programa recién instalado solo en una ventana que se abrió después de la instalación.

2. Instalar uv

Este comando instala uv con winget, la herramienta de paquetes de Windows. Escríbalo y pulse Enter:

Parte 2: Escribe la búsqueda

En esta parte escribes la búsqueda en la pantalla Query de la aplicación. La búsqueda es la lista de palabras que la aplicación envía a la base de datos. El ejemplo de esta guía busca en OpenAlex baseball, pose estimation y pitcher, para los años 2015 a 2026. Guardar la búsqueda no busca nada: solo escribe la búsqueda y los años en la carpeta de tu proyecto.

1. Añade los términos de búsqueda

Haz clic en el recuadro debajo de Search terms, escribe una palabra o una frase y pulsa Enter. La palabra aparece como una ficha, un recuadro pequeño con un botón para quitarla. Cada término de búsqueda es una alternativa: la aplicación los une con OR, así que un registro coincide si tiene al menos uno de ellos.

El ejemplo de la guía no usa términos de búsqueda, así que deja este recuadro vacío.

2. Añade el término compuesto

Un término compuesto es un grupo de partes que deben aparecer todas. Haz clic en el recuadro debajo de Compound terms, escribe baseball + pose estimation + pitcher y pulsa Enter. Deja un espacio a cada lado del signo más. Sin los espacios, todo el texto se convierte en una sola frase.

La aplicación guarda un término compuesto como sus partes entre comillas, unidas por AND. Para el ejemplo, la aplicación guarda esta línea en el archivo del proyecto (project.toml):

search = '"baseball" AND "pose estimation" AND "pitcher"'

El texto entre las comillas simples exteriores es la búsqueda: "baseball" AND "pose estimation" AND "pitcher".

3. Indica los años

En First year, escribe 2015. En Last year, escribe 2026. Hacen falta los dos. Los mismos años se copian a la pantalla Criteria, como Include from year e Include up to year, así que también se aplican como regla de cribado.

4. Deja Subject areas vacío

Deja Subject areas vacío en este ejemplo. Una lista vacía significa sin restricción. Un recuadro vacío no significa que no coincida nada.

5. Guarda la búsqueda

Pulsa Save query. La pantalla muestra entonces Query saved to project.toml and criteria.yaml.

Puedes seguir cambiando la búsqueda hasta que empiece la primera captura. Después, la pantalla Query muestra un aviso que empieza por Read-only. y da el motivo. Cuando ya ha empezado una ejecución, el aviso dice: The query is read-only because a Run has started. A different search needs a new Project. Una ejecución que descartaste también cuenta, así que sigue bloqueando la búsqueda.

Si algo no sale bien

  • Add at least one search term or compound term. Añade el término compuesto del paso 2 y pulsa Save query otra vez.
  • OpenAlex searches have no grouping in this version: use search terms only, or a single compound term on its own. Quita los términos de búsqueda, para que solo quede el término compuesto.
  • Enter both the first and the last year. Escribe 2015 y 2026, y guarda otra vez.
  • El aviso Read-only. permanece una vez que ha empezado una ejecución. No hay ningún error. Para buscar de otra manera, empieza un proyecto nuevo.

El recuento del ejemplo

El ejemplo devolvió 108 registros el 2026-11-05, la fecha que documenta el repositorio. Hoy el número puede ser distinto, porque los recuentos de OpenAlex cambian con el tiempo. La parte 3 muestra dónde aparece el recuento de registros en la aplicación.

Si tienes Scopus

Lee esto solo si tu modo de fuente usa Scopus. Los pasos anteriores siguen valiendo. Hay tres diferencias. Esta guía no recorre una captura de Scopus.

  1. Subject areas aparece desactivado, y la pantalla explica por qué: Restricting by subject area with Scopus needs Enrichment, which this version does not offer.
  2. En la comprobación de tamaño, Check the size of the Scopus search muestra el coste de cuota y la cuota semanal que queda, como Quota cost y Remaining weekly allowance. No muestra cuándo se reinicia. La comprobación de OpenAlex sí muestra cuándo se reinicia su cuota diaria.
  3. Una captura necesita una clave con derecho a la vista completa, que el software llama COMPLETE. Si tu clave no lo tiene, la aplicación rechaza la captura y no recurre a una vista inferior. La pantalla muestra entonces el mensaje general sobre la clave A key is missing, or the service did not accept it. y sugiere revisar la clave. Una clave válida también puede mostrar ese mensaje, porque el rechazo se refiere a la vista. La comprobación de tamaño no necesita la vista completa, así que puede funcionar antes de que una captura sea rechazada.

Elsevier y tu institución deciden qué vistas puede usar tu clave. Solo lo sabes al intentarlo.

Para la diferencia entre una búsqueda y los criterios, lee la página titulada Build a Scopus Query en esta documentación. Puedes abrirla aquí: Build a Scopus Query.

Parte 3a: Iniciar la aplicación y prepararla

En esta parte inicias la aplicación, eliges la carpeta donde se guardan tus Projects, creas un Project y guardas una clave gratuita de OpenAlex. En esta parte no se ejecuta ninguna búsqueda.

Iniciar la aplicación

En la terminal, ejecuta el comando siguiente. La aplicación se inicia en tu equipo y se abre en tu navegador. Mantén abierta la ventana de la terminal mientras usas la aplicación. Si cierras esa ventana, la aplicación también se detiene.

prismabib gui

Después, la terminal muestra una línea como esta:

prismabib is running at http://127.0.0.1:5006/ (Ctrl+C to stop)

La dirección apunta a tu propio equipo: 127.0.0.1 es la dirección local. El número 5006 es el puerto habitual. Si ese puerto está ocupado, la aplicación elige otro y muestra su dirección.

Si el navegador no se abre solo, copia la dirección de la terminal y pégala en la barra de direcciones de tu navegador.

Si algo sale mal

  • El navegador no se abrió: copia la dirección que muestra la terminal y pégala en tu navegador.
  • La terminal dice que no encuentra el comando: la instalación de la Parte 1 no terminó. Ejecuta otra vez la línea de instalación de la Parte 1, abre una ventana de terminal nueva y ejecuta el comando de nuevo.
  • La terminal dice No free port: cierra los programas que puedan estar usando puertos de red y ejecuta el comando de nuevo.

Detener la aplicación

Para detenerla, haz clic en “Stop the app” en la pantalla Home. Si no hay nada en ejecución, la aplicación se detiene de inmediato y la página del navegador indica que se detuvo. Entonces puedes cerrar la pestaña.

Si hay una tarea en ejecución, como una captura, la aplicación pide confirmación primero. La página muestra “Yes, stop the app” y “Keep the app running”. Elige “Yes, stop the app” para detenerla: la captura en curso se detiene, las páginas ya descargadas se conservan y una captura posterior continúa a partir de ellas. Elige “Keep the app running” para seguir sin detenerla.

También puedes pulsar Ctrl+C en la terminal. Cuando no queda nada en ejecución, la terminal muestra:

prismabib has stopped. Nothing running was left behind.

Elegir la carpeta de Projects

La pantalla Home tiene un campo llamado “Projects folder”. La aplicación guarda cada Project en su propia carpeta dentro de esta, y la pantalla muestra la carpeta en uso. Hasta que elijas una carpeta, la aplicación usa una carpeta llamada projects dentro de la carpeta en la que estaba la terminal al iniciar la aplicación.

  1. Escribe una ruta en “Projects folder”.
  2. Si la carpeta ya existe, haz clic en “Use this folder”. Si todavía no existe, haz clic en “Create this folder” y la aplicación la crea.
  3. Lee la línea que aparece debajo de los botones. Si la carpeta se acepta, la línea empieza con “Using” y muestra la carpeta. La aplicación recuerda esa carpeta para la próxima vez.

Evita una carpeta dentro de un servicio de sincronización como OneDrive, Dropbox, Google Drive, iCloud o Box Sync. En ese caso la aplicación muestra una advertencia, pero acepta la carpeta. La sincronización puede bloquear o cambiar archivos mientras la aplicación escribe en ellos, así que una carpeta fuera de la sincronización es más segura.

La aplicación rechaza tres tipos de carpeta y explica el motivo debajo de los botones: una carpeta en la que no puede escribir, una ruta demasiado larga y una carpeta dentro del programa instalado. Un rechazo no cambia nada, así que puedes elegir otra carpeta de inmediato.

Si algo sale mal

  • El mensaje dice que la carpeta no existe: haz clic en “Create this folder” o revisa cómo escribiste la ruta.
  • El mensaje dice que prismabib no puede escribir en esta carpeta: elige una carpeta en la que tu cuenta pueda guardar archivos.
  • El mensaje dice que la ruta es demasiado larga: elige una ruta más corta.

Crear un Project

Un Project contiene una revisión sistemática: su query, sus criterios de elegibilidad, sus Records y sus Decisions. La aplicación nunca sobrescribe un Project. Si ya existe una carpeta con el mismo nombre, la aplicación te pide que elijas otro nombre de Project.

  1. En la pantalla Home, haz clic en “New Project”.
  2. En “Project name”, escribe un nombre, por ejemplo My first review. La aplicación convierte el nombre en un nombre de carpeta y lo muestra debajo del campo.
  3. En “Reviewer name”, escribe tu nombre. Cada Decision de este Project lleva ese nombre. La aplicación lo recuerda para el siguiente Project.
  4. Responde a “Do you have Scopus access?” eligiendo “Yes”, “No” o “Not sure”. La aplicación no tiene una respuesta por defecto, así que debes elegir una.
  5. Haz clic en “Create Project”.

Tener acceso a Scopus significa tener una clave de Scopus con la vista COMPLETE, que normalmente se obtiene a través de una institución, como una universidad. Si no lo sabes, elige “Not sure”.

Tu respuesta define la Source mode, es decir, qué bases de datos busca esta revisión. Con “No” o con “Not sure” se crea un Project con Source mode openalex, que busca solo en OpenAlex. Esa ruta necesita una clave gratuita de OpenAlex, que obtienes más abajo en esta parte, y no pide ninguna clave de Scopus. Esta parte no explica la ruta de Scopus.

Cuando el Project se crea, la pantalla muestra:

Project my-first-review created with Source mode openalex.

El Project se abre en su primer paso que no está terminado, “Query”. La Parte 2 de esta guía explica ese paso.

Si algo sale mal

  • La aplicación dice que ya existe un Project o una carpeta con ese nombre: escribe otro “Project name”.
  • La aplicación pide escribir el nombre del revisor: escribe tu nombre en “Reviewer name”.
  • La aplicación dice que la ruta es demasiado larga: elige un nombre de Project más corto o una carpeta de Projects más corta.
  • La aplicación pide responder a la pregunta sobre Scopus: elige “Yes”, “No” o “Not sure”.

Obtener una clave gratuita de OpenAlex

Una búsqueda real de OpenAlex necesita una clave. La clave es un código que identifica tu cuenta. Crea una cuenta gratuita en el sitio web de OpenAlex, openalex.org, y copia desde allí tu clave de API.

Guardar la clave y probarla

Las claves se guardan en tu archivo de configuración personal, que está fuera de cualquier carpeta de Project. La introduces en la parte “Keys” del paso “Source mode and keys”.

  1. En la pantalla Home, haz clic en el botón Open que está junto a tu Project, en la lista de Projects.
  2. En la barra lateral, haz clic en “Source mode and keys”. La parte “Keys” muestra el archivo de configuración en una línea que empieza con “Keys are saved in your per-user settings file”, seguida de su ubicación.
  3. Pega tu clave en “OpenAlex API key”. El campo muestra puntos en lugar de los caracteres, así que la clave no aparece en pantalla.
  4. Haz clic en “Save OpenAlex key”. La aplicación indica que la clave se guardó y vacía el campo.
  5. Haz clic en “Test OpenAlex key” y lee la línea que muestra.

Cuando la clave es aceptada, la aplicación muestra The key works. La línea que empieza con “OpenAlex key comes from” indica de dónde lee la aplicación la clave. Puedes cambiar la clave más adelante en la misma pantalla: pega una nueva, guárdala y vuelve a probarla.

Si algo sale mal

  • El resultado dice no key is set: pega la clave en “OpenAlex API key” y haz clic primero en “Save OpenAlex key”.
  • El resultado dice 401: the key was rejected: copia la clave otra vez desde tu cuenta de OpenAlex, pégala, guárdala y prueba de nuevo.
  • El resultado dice 403: revisa que tu cuenta tenga permiso para usar este servicio y prueba de nuevo.
  • El resultado es un error de red: revisa tu conexión y prueba de nuevo.

Parte 3: Usar la aplicación de principio a fin (continuación)

Esta parte lleva desde la consulta guardada hasta un almacén construido. Guardas las reglas, compruebas el tamaño de la búsqueda, capturas los resultados y construyes el almacén. Los nombres de botones y campos van en negrita y se citan exactamente como aparecen en inglés en la aplicación.

Guardar los criterios

La pantalla Criteria contiene las reglas que un Record debe cumplir para seguir en la revisión, y los códigos de motivo que eliges al excluir un Record. Escribe los códigos de motivo para el cribado de resúmenes en Reason codes for excluding at abstract screening, uno por línea. El cribado de texto completo tiene su propia lista, en Reason codes for excluding at full-text screening.

En el Screener pulsas e y luego una tecla numérica para elegir un motivo. El primer código de la lista es la tecla 1, el segundo la tecla 2, y así hasta la tecla 9. Un código después del noveno no tiene tecla numérica, pero puedes elegirlo con el ratón.

Escribe la versión en Criteria version (MAJOR.MINOR.PATCH) como tres números separados por puntos, por ejemplo 1.0.0. Sube la versión cada vez que cambies una regla, para que el historial de tus reglas siga claro. Los comentarios del archivo de criterios también piden guardar cada cambio en git.

Pulsa Save Criteria. La pantalla confirma el guardado con la versión que escribiste:

Criteria version 1.0.0 saved to criteria.yaml.

Si algo sale mal

  • Un mensaje junto a un campo indica que el valor no es una versión semántica. Escribe tres números separados por puntos, por ejemplo 1.0.0, y vuelve a pulsar Save Criteria.
  • La pantalla dice Some entries need correcting. Lee el mensaje junto a cada campo, corrígelo y vuelve a pulsar Save Criteria.
  • La pantalla dice The Criteria are read-only because a Decision has been logged. Cuando el cribado ha empezado, los criterios no se pueden cambiar en la aplicación. Esta guía no explica la ruta de línea de comandos.
  • La pantalla dice criteria.yaml has changed since you opened this form. No se guardó nada. Sal del paso Criteria, vuelve a abrirlo y escribe tus cambios de nuevo.

Comprobar el tamaño de la búsqueda

Pulsa Check the size of the OpenAlex search antes de cualquier captura. La comprobación envía una sola solicitud a OpenAlex y no captura nada. No escribe nada en tu Project, así que puedes repetirla cuantas veces quieras. Para el ejemplo, la pantalla muestra líneas como estas:

Records: 108
Cost bound: $0.00
Page budget: 2 pages
Remaining daily allowance: un número que devuelve OpenAlex
Allowance resets: una fecha y hora en tu zona horaria local

La línea que empieza por Records indica cuántos Records encuentra la búsqueda en OpenAlex en el momento de la comprobación. Tu número puede ser distinto del ejemplo. La comprobación lee el recuento de OpenAlex cada vez que pulsas el botón, y la página Getting Started indica que esos recuentos cambian con el tiempo. El ejemplo devolvió 108 Records el 2026-11-05. Una cifra distinta no es un error.

Después, la comprobación aplica tres reglas al recuento de Records:

  • 2.000 Records o menos: la comprobación pasa y puedes continuar.
  • Más de 2.000 y hasta 10.000 Records: la aplicación muestra un aviso. Marca I understand this is a large set and want to continue para seguir.
  • Más de 10.000 Records: la aplicación bloquea la búsqueda e indica el siguiente paso, que es reducir la consulta. Para reducirla, ve a la pantalla Query, cambia los términos o los años, pulsa Save query y vuelve a comprobar.

En OpenAlex, la pantalla muestra además tu asignación diaria: cuánta queda, en las unidades propias de OpenAlex, y cuándo se restablece. La hora de restablecimiento se muestra en tu hora local. La búsqueda en OpenAlex tiene un límite diario de 1.000 páginas, y una captura cuenta contra ese límite.

Si tu Project busca en Scopus, la comprobación muestra en su lugar el coste de cuota. Es el número de solicitudes que usaría la captura, junto con la asignación semanal restante. La pantalla no indica hora de restablecimiento para Scopus.

Cuando la comprobación pasa, pulsa Continue to capture. Debajo aparecen los controles de captura.

Si algo sale mal

  • La pantalla dice que hace falta una clave para comprobar el tamaño. Pulsa Go to the keys step, añade la clave y luego vuelve a pulsar Check the size of the OpenAlex search.
  • Continue to capture aparece en gris. La comprobación bloqueó la búsqueda, o hay un aviso que espera tu marca. Si está bloqueada, reduce la consulta; si solo avisa, marca la casilla.
  • Aparece una frase en negrita debajo de la comprobación con el problema y el siguiente paso. Léela, sigue el paso y vuelve a comprobar. La consulta guardada no ha cambiado.

Capturar la búsqueda

Capturar trae los resultados de la búsqueda desde OpenAlex y guarda cada página tal como llegó. Ajusta Page budget (pages of 100 works) al máximo de páginas que puede traer esta ejecución. El campo empieza en 10. El ejemplo necesita 2 páginas, así que escribe 2. Una captura que llega a su presupuesto se detiene, y puedes reanudarla después.

OpenAlex llama "works" a los elementos que devuelve. Esta guía y la aplicación llaman Records a esos mismos elementos, así que el presupuesto de páginas cuenta páginas de 100 Records cada una.

Marca I confirm: capture this search now y pulsa Start the capture. La aplicación desmarca la casilla después de cada inicio, incluida una reanudación, así que la marcas de nuevo cada vez.

Mientras se ejecuta, la pantalla muestra una barra de progreso y recuentos como estos:

Running. You can close the browser; the capture keeps going.
Pages done: 1. Records seen: 100 of 108.

Cerrar el navegador no detiene la captura mientras la aplicación esté en marcha. Mantén abierta la ventana de la terminal, porque la aplicación sigue funcionando en ella.

Para pausarla, pulsa Cancel the capture. La captura se detiene después de guardar la página que está trayendo, y las páginas ya traídas se conservan. Pulsa Resume the capture más tarde para continuar desde el mismo punto.

Cuando se han traído todas las páginas, la ejecución se marca como Sealed:

Sealed. The capture is finished and can no longer be changed.

Una Sealed run está completa, y la aplicación nunca la cambia.

Si algo sale mal

  • La pantalla dice Check the size of the saved query first; it has changed or not run. Pulsa de nuevo Check the size of the OpenAlex search, luego marca la casilla e inicia.
  • La pantalla dice Confirm that you want to capture before it starts. Marca I confirm: capture this search now y pulsa Start the capture.
  • La pantalla dice que la red se detuvo y que las páginas ya traídas se conservan. Revisa tu conexión a internet y pulsa Resume the capture.
  • La pantalla dice que la asignación diaria de OpenAlex está agotada y muestra cuándo se restablece, en tu hora local. Espera hasta esa hora y pulsa Resume the capture.

Capturar de nuevo, o descartar una ejecución sin sellar

Capture again (a new run) inicia una nueva ejecución de la misma búsqueda, aunque ya exista una Sealed run. La Sealed run se queda como está. La nueva ejecución envía solicitudes nuevas a OpenAlex, así que vuelve a gastar tu asignación diaria. Úsala solo cuando necesites una captura nueva.

Para descartar una ejecución sin sellar que no quieres, pulsa Discard the unsealed run. La aplicación te pide confirmar con Yes, discard it. Pulsa Keep it si cambias de opinión. Descartar no borra nada: las páginas ya traídas siguen en el disco, y la ejecución descartada nunca se reanuda ni se sella.

Si algo sale mal

  • La pantalla dice This capture is already Sealed. Una Sealed run no se puede capturar en su lugar. Pulsa Capture again (a new run) para iniciar una nueva ejecución.
  • La pantalla dice The capture is running. Cancel it before discarding. Pulsa Cancel the capture, espera a que se detenga y después descarta.
  • Discard the unsealed run aparece en gris. Solo se puede descartar una ejecución sin sellar; una Sealed run no se puede descartar.

Construir el almacén

El almacén es el conjunto de Records construido a partir de tus búsquedas capturadas. Pulsa Build the store. Después de la primera construcción, el botón dice Rebuild the store. Mientras se construye, la pantalla dice Building. y muestra el progreso.

Cuando termina la construcción, la pantalla muestra el resultado. Para el ejemplo, se ve así:

Built. The store holds 108 Records. 0 duplicates across searches were removed.

Tus números serán los tuyos. Un Record que devuelven varias búsquedas se cuenta una sola vez, y el segundo número indica cuántos duplicados se eliminaron.

Reconstruir nunca toca tus búsquedas capturadas ni tus Decisions. La aplicación reemplaza el almacén solo cuando el nuevo está completo. Para detener una construcción en curso, pulsa Cancel the build. La aplicación dice Stopped as you asked. y conserva el almacén anterior.

Si algo sale mal

  • La pantalla dice The build failed. Lee la frase que sigue, corrige el problema que indica y pulsa Rebuild the store, o Build the store si todavía no hay almacén.
  • El almacén parece desactualizado tras nuevas capturas. Pulsa Rebuild the store. Reconstruir conserva tus búsquedas capturadas y tus Decisions.

Borrar el almacén construido

Borrar el almacén construido es seguro, porque puedes construirlo de nuevo a partir de tus búsquedas capturadas. Pulsa Delete the built store. La aplicación muestra qué se borra y qué se conserva. Pulsa Yes, delete the store para borrarlo, o Keep the store para conservarlo.

Solo se borra el almacén construido. Tus búsquedas capturadas y cada Sealed run se quedan, y también se quedan tu Decision log, el archivo de ajustes del Project y su archivo de Criteria. La aplicación nunca borra ninguno de estos. Después de borrar, la pantalla dice:

The store was deleted. Build the store to make it again.

Si algo sale mal

  • La pantalla dice A task is running. Espera a que termine, o pulsa Cancel the capture o Cancel the build, y luego borra de nuevo.
  • La pantalla dice The store could not be deleted, probably because another program has it open. Cierra ese programa y pulsa Delete the built store otra vez.
